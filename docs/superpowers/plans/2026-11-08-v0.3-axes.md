## Axe 1 — Sauvegardes fiables

### 1a. Points de restauration locaux (`storageService.ts`)
- Clé séparée `${storageKey(campaignId, slot)}:snapshots` → `Snapshot[]`, plus récent en premier, **10 max**.
- `type Snapshot = { at: number; label: string; state: string }` (state = JSON exporté).
- `listSnapshots(campaignId, slot): Snapshot[]` — tolère clé absente/corrompue (renvoie `[]`).
- `addSnapshot(state, slot, label, now = Date.now()): string | null` — ajoute en tête, tronque à 10 ; sur dépassement de quota, retire le plus ancien et réessaie jusqu'à réussite ou liste vide ; renvoie un message d'erreur ou `null`.
- `restoreSnapshot(snapshot, campaign): GameState` — passe par `importGame` (validation).
- Points automatiques : fin de combat (« Fin de combat : <nom> »), repos long, repos court, **avant un import** (« Avant import ») et **avant une restauration** (« Avant restauration »). Bouton manuel « Créer un point de restauration ».
- UI (Paramètres) : liste date + libellé, « Restaurer » avec confirmation, annonce du résultat.

### 1b. Fichier de sauvegarde automatique (File System Access, Chromium seulement)
- Si `'showSaveFilePicker' in window` : bouton « Lier un fichier de sauvegarde » dans Paramètres ; sinon le bloc n'apparaît pas.
- Après chaque sauvegarde réussie, écriture du JSON dans le fichier lié (débounce ~1,5 s, une écriture à la fois). Succès → `markExported` (le rappel d'export ne réclame plus). Échec → annonce + fichier délié.
- Affiche le nom du fichier et la dernière écriture ; bouton « Délier ».
- Logique d'écriture isolée et testable (`createFileAutosave(write, delay)` ou équivalent) avec un faux handle.
- shortcut : le handle n'est pas persisté (IndexedDB) ; il faut relier le fichier à chaque session.

## Axe 2 — Entre les combats

### 2a. Repos court (`game.ts`)
- `shortRest(state, campaign, healing: Record<playerId, number>): GameState` — refusé pendant un combat non terminé (même règle que `longRest`). Pour chaque PJ vivant (pas `dead`) : `hp = min(maxHp, hp + healing[id])` (entiers ≥ 0, sinon erreur) ; un PJ à 0 PV soigné > 0 redevient `active` avec sauvegardes contre la mort à zéro. Journal type `rest`, titre « Repos court », description « Alda +5 PV, Bren +0 PV ».
- Les dés de vie restent à la main du MJ (pas modélisés) : il saisit les PV récupérés.
- UI : bouton « Repos court » à côté de « Repos long » (panneau du groupe), dialogue intégré (pas de `prompt`) avec un champ numérique par PJ vivant, validation, désactivé pendant un combat.

### 2b. Points d'expérience (`game.ts` + nouveau `services/xp.ts`)
- `XP_BY_CR` : table officielle D&D 5e 2014 (0 → 10, 1/8 → 25, 1/4 → 50, 1/2 → 100, 1 → 200, 2 → 450, 3 → 700 … 30 → 155000). `xpForChallenge(challenge: string): number | null` (FP inconnu/vide → `null`).
- `GameState.xp?: Record<playerId, number>` (entier ≥ 0, validé à l'import).
- `finishEncounter` : créatures vaincues = participants non-PJ et non-`ally` au statut `dead` ou `unconscious` (pas les retirés). XP totale répartie à parts égales (arrondi inférieur) entre les PJ du combat non morts. Ajoute au récapitulatif « XP : 150 (50 chacun) » et « XP non calculée : <noms> (FP inconnu) » le cas échéant ; cumule dans `state.xp`.
- UI : XP affichée sur la fiche de chaque PJ (CharactersView) avec un champ d'ajustement manuel.

### 2c. Préparation de session (Dashboard)
- Fonction pure `sessionPrep(state, campaign)` → `{ scene, nextScenes, encounters: { encounter, needsPrep: boolean }[], warnings: string[] }` : scène active, scènes atteignables par ses choix/liens, rencontres de ces scènes (needsPrep = quantité ou stat indispensable manquante, même règle que `EncounterPreparation`), avertissements de données qui concernent ces scènes/rencontres.
- UI : section « Préparer la session » sur le tableau de bord, liens vers scène/rencontre.

## Axe 3 — Écran des joueurs

- Ouverture : bouton « Écran des joueurs » (barre du haut) → `window.open('?ecran=joueurs', 'grimoire-joueurs')`. `main.tsx` rend `PlayerScreen` si `?ecran=joueurs`, sinon `App`.
- Transport : `BroadcastChannel('grimoire-joueurs')`. Messages : `{ type: 'hello' }` (écran → MJ) ; `{ type: 'view', view: PublicView }` (MJ → écran, à chaque changement et en réponse à `hello`).
- `services/playerScreen.ts` : `publicView(state, campaign, reveal): PublicView` **pure** :
  - `combat: null | { name, round, order: { id, name, kind: 'player' | 'creature', active: boolean, hp?: string, status?: 'À terre' | 'Stable' | 'Mort' | 'Vaincu' }[] }` — ordre d'initiative, retirés exclus ; `hp` (« 12/20 ») **uniquement pour les PJ** ; jamais PV/CA/initiative des monstres.
  - `reveal: null | { title: string; text: string }`.
- Révélation : bouton « Montrer aux joueurs » sur le texte à lire d'une scène (source ou ajout du MJ) ; « Effacer l'écran des joueurs ». Le contenu révélé n'est pas sauvegardé.
- `PlayerScreen` : grand format lisible à distance, thème existant, rien d'interactif hormis plein écran ; message d'attente si aucun MJ connecté.
